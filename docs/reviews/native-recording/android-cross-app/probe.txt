# WHERE THE AUDIO COMES FROM (truthful attribution):
# A constant full-scale 220 Hz sine (RMS -3.01 dBFS = sine at amplitude 1.0). It is the Android EMULATOR's own built-in-mic
# fallback: AOSP device/generic/goldfish hals/audio/device_port_source.cpp, DevicePortSource::create(): for
# AUDIO_DEVICE_IN_BUILTIN_MIC, when the tinyalsa capture source can't be created it logs "creating a tone source instead"
# and the final fallback is RepeatGenerator(generateSinePattern(sampleRate, 220.0, 1.0)).
# (https://android.googlesource.com/device/generic/goldfish/+/refs/heads/main/hals/audio/device_port_source.cpp, fetched 2026-10-05)
# Pocket QA code has no tone generator (grep sine/ToneGenerator/AudioTrack: none in recorder code).
# Observed on the same emulator (dumpsys audio, recording history):
#   10-05 19:07:31:010 rec start riid:79 uid:10224 session:81 src:MIC not silenced pack:com.reshareai.pocketqa
#   10-05 19:11:21:674 rec stop  riid:79 uid:10224 session:81 src:MIC not silenced pack:com.reshareai.pocketqa   (230.7 s = this clip)
# Observed LIVE during the next recording (lifecycle run, 19:19:30), logcat of the emulator audio HAL:
#   W android.hardware.audio@7.1-impl.ranchu: create:453 failed to create alsa source for 'AUDIO_DEVICE_IN_BUILTIN_MIC'; creating a tone source instead.
#   dumpsys audio: session:97 -- source client=MIC, dev=1ch 44100Hz ENCODING_PCM_16BIT -- pack:com.reshareai.pocketqa -- silenced:false
# So: the emulated microphone delivered a synthetic tone, Pocket QA captured it live via MediaRecorder AudioSource.MIC and muxed
# it with the screen at recording time. Nothing was added after recording. It is NOT a human voice: real narration on a
# physical phone remains a device gate. The gRPC injectAudio path (inject-tone.py) stays BLOCKED (emulator crash, see that file).
