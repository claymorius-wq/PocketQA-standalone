# pqa-qa security verdict, cloud increment 3, round 1 (verbatim pane output; frozen tree 17c12a37)

⏺ I used only Read; Grep and Glob weren't available. I modified nothing, used no subagents, and opened no .preview*,
  preview-data, .env* or credential files. The storage design is sound; I found no P0–P2, and five P3s remain.

  What holds up
  - Object keys: always generated by the server (quarantine/<intentId>, evidence/<evidenceId>, or the existing plain
    ids), and every adapter call checks them against SAFE_KEY first (storage/types.ts:24-27). No client input ever
    becomes a key or a path.
  - Final objects can't be overwritten: no presigned URL is ever issued for an evidence/ key. Quarantine keys are swept
    after the intent closes and its expiry passes, and every presigned URL expires no later than its intent
    (evidence.ts:280), which catches re-PUTs after completion (sweep.ts:37-43).
  - Presigned PUTs: scoped to one key, signed over content-type and content-length (r2.ts:50-56), and valid for at most
    10 minutes within a 15-minute intent.
  - Quota and races:
    - The quota counts evidence plus the bytes declared by open intents, inside the creation transaction.
    - One open intent per segment is enforced by a unique index.
    - Completion claims the intent atomically (pending to completing, :306-309), checks size and type, copies to the
      final key, then re-checks state, duplicates and quota in a transaction before inserting the evidence.
    - Every failure path either rejects and deletes, returns the intent to pending for retry, or deletes the copy.
  - Submission: blocked while intents are open (participations.ts:53-57).
  - Playback: still behind the use-time permission re-check for an active holder, with ranges, no-store and nosniff.
    Nothing is served by direct URL.
  - Deletion: account deletion removes objects through the retried outbox and closes open intents along with their
    quarantine objects. The sweep cleans up crash-abandoned completions and retries the outbox with backoff.
  - Credentials: R2 keys stay in server config. GET /config exposes only the storage mode, and the app's PUT carries no
    bearer token (client.ts:121-137).
  - Shared demo: r2 is refused together with the shared demo (config.ts:129-130), start.sh pins local storage, and the
    gate still blocks uploads.
  - Local mode: unchanged, and direct uploads are refused there.
  - Evidence: the tests and mutations S1–S8 back all of this, and pnpm verify passes.

  Findings (all P3, non-blocking)

  1. [P3] New bytes can be swapped in between the type check and the copy. evidence.ts:303-333: HEAD and the 16-byte
     sniff read the quarantine object, then copy reads it again. During that window, a tester holding the still-valid
     presigned URL can PUT different bytes of the same signed length and type, and the unchecked bytes become the final
     evidence.
     - The impact is small: a 16-byte sniff can already be satisfied by prefixing valid magic bytes, and playback uses
       the database's type plus nosniff. But it breaks the plan's "no post-validation overwrite".
     - Fix: Use the ETag from HEAD for GetObject IfMatch during the sniff and for CopySourceIfMatch on the copy, and
       treat a mismatch as retryable. Teach the fake S3 about ETags and test a swap.
  2. [P3] Status resets can undo a concurrent close. evidence.ts:310, :322, :331: setStatus updates by id only.
     - Scenario: account deletion (or the sweep) closes a completing intent while the completion's copy fails. The
       copy-failure path then sets it back to pending, reopening an intent for a deleted account. It's harmless today,
       because the next sweep expires it again.
     - Fix: Make these updates conditional, ... WHERE id = ? AND status = 'completing'.
  3. [P3] The fake S3 can't prove that R2 enforces the signed headers. It doesn't check signatures or the signed
     content-length and content-type, and the candidate says so.
     - Fix: At the real-R2 gate, record a test where a PUT with a different length or type is refused, plus
       exact-origin CORS and public access off.
  4. [P3] The type check is a 16-byte signature match, not real validation. The plan asks to "verify actual bytes and
     container", but the check accepts any file that starts with the right magic bytes. That's acceptable for an MVP
     served with the stored type and nosniff.
     - Fix: Note this as a limit in ADR 0005 §3. Before real-data production, parse the MP4/WebM box structure (or run
       a server-side probe) when completing.
  5. [P3] The sweep and outbox assume one API process. Already documented; for multi-instance hosting, use a single
     runner or a database lease so two processes don't sweep or retry the same rows at once.

  VERDICT: APPROVE
